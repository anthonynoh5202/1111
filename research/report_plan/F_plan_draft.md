## 1. 판단 규칙 (기본값은 관망)
- "진입 가능"은 모두 통과할 때만: ① 차트프로 진입 조건 중 하나 성립(엔진 판정) ② 쉬는 구간 아님(이평 확산·역배열·박스·지표 발표 전후 창) ③ 손익비 목표2 ≥ 2(비용 포함) ④ 손절 시 계좌 손실 ≤ 단계 상한(5만 원 단계 3%) ⑤ 청산 거리 규칙 L1 ⑥ 살아 있는 기준마디 반대 방향 아님(트랩 예외) ⑦ GLM 반대 의견이 반대 방향이 아님.
- 하나라도 실패하면 "관망"과 사유, 재검토 가격(예: "82,581 이하 지정가면 위험 3% 이내")을 보여 준다.
- 레버리지: 격리, L1(청산 거리 ≥ max(손절×2, 손절+3%p)) 만족하는 가장 높은 정수 배수, 상한 20배. "레버리지는 증거금 크기일 뿐, 잃는 돈은 손절이 정함"을 매번 한 줄로. 주문 체크리스트 5개(격리·One-way, 자동 증거금 추가 끄기, BTC 단위 0.001, TP/SL 동시 설정, 청산가 확인).
- 검증 상태 배지: 지금은 "우위 미확인 · 모의 기록 n건".

## 2. 시스템 (C 기준)
- 실행: 처음 2~4주 맥(launchd 감시자 → 상주 프로세스(일정·텔레그램 토큰만) → 매시간 작업 프로세스(데이터·계산·AI·그림, AI 키만)), 가동률 95% 미만이면 도쿄 서버(월 $5~12).
- 일정: HH:00:20 시작 → HH:03 전송, HH:10 지연 표시, HH:15 포기·경고, 놓친 시간 소급 없음.
- 데이터: 바이낸스 공개 REST(1h·4h·1d 봉, premiumIndex, openInterest·Hist, exchangeInfo), 통계는 매시간 DB 저장. 웹소켓 없음.
- 대체 경로: Claude → GLM → 엔진 템플릿. 하트비트(healthchecks.io), 비용 3중 상한(코드·콘솔·GLM 선불).
- 보안: 비밀 3개(Anthropic·GLM·텔레그램)는 ~/.config/btcreport/secrets(700/600), 보고서용 새 텔레그램 봇, 민감 정보는 텔레그램에 보내지 않음, 보고서 전용 해시 고정 설치 목록, 맥 파이썬 3.14.

## 3. 비용 (월)
- Claude (b+) $60~85, GLM $10~18, 서버(필요 시) $5~12 → 약 $75~115(약 10~16만 원). 계좌보다 큼 → 시험 단계는 연구비. 절약 모드: Opus 하루 2~3회 $41~61.

## 4. 검증·운영 (A4)
- 기록 29항목(엔진만의 판단 포함), 1분봉 채점(MFE/MAE), 관망 채점(롱·숏 탐침), 사용자 실제 매매 기록(체결가·준수 여부), 주간 복기.
- 합격선 10개(겹치지 않는 300건+, 평균 ≥ +0.10R & 95% 하한 > 0, 다중 검정 보정, 기준선 초과, 비용 2배에도 플러스 등). 지금까지 통과 0.
- LLM 층 가치: 엔진만 vs 엔진+Claude 짝 비교 6~12개월.

## 5. 만드는 순서
1. 계산 엔진 + PDF·사진(AI 없음) + 매시간 무음 상태 카드 + 기록 DB
2. 텔레그램 전송·명령(/now /status /history /pause /resume + 한글 버튼)·맥 설치 스크립트
3. Claude 정식 분석 + 검사기 + 비용 상한
4. GLM 반대 의견·대체
5. 맥에서 1~2주 관찰 + 바이낸스 데모 매매 병행
6. 5만 원 실전(사다리 1단계)

## 6. 사용자 확인 필요
- GLM 키 종류(종량제 vs 코딩 플랜), Claude API 예산 출처(회사/개인), 한국에서 바이낸스 이용 문제(2026-01 구글 앱 차단 보도), 맥 상시 가동 가능 여부, 데모 단계 동의.

## 7. 하지 않을 것
- 매시간 Opus 전체 분석, AI가 가격·레버리지·수량을 직접 씀, 차트 이미지를 AI 기본 입력으로, 펀딩·OI·롱숏으로 방향 판단, 우위 확인 전 증액, 3배 고정 레버리지(이 계좌에선 증거금이 계좌의 78%).
