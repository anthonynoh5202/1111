- 손절은 지시대로 **허리(80.8k) 바로 아래가 아니라 9/20 저점(80,095.9) 아래 79,800**으로 고쳤다. 근거는 [CP-17-7] "허리 바로 아래에 컷을 붙이지 않는다", [CP-07-4] 절대 기준가(상승이 시작된 변곡점).

- 왜 "진입가를 옮기는" 대안을 안 썼나: 손절 79,800을 두고 위험 3%를 맞추려면 진입이 80,759 이하여야 한다(a1_sizing `entry_limit_for_cap`). 그 가격은 허리(80.8~81.1k) 아래라 차트프로 규칙상 매수하지 않는 자리다([CP-06-1]). 그래서 재검토 조건은 "82.3k 부근에서 더 좁은 1시간봉 손절이 잡히는 자리"로 썼다.
- 진입 불가일 때 참고 계획을 차트 아래로 내리는 "바뀌는 배치"도 생각했다. 하지만 매번 같은 자리에 같은 항목이 있어야 빨리 읽힌다고 보고 배치는 고정했다. 그 대신 검사기 칸을 계획 타일보다 위에 둔다.

### 1.2 차트 1개 (가운데)

- **봉: 4시간봉 60개**(9/19 09시 봉 ~ 9/29 05시 봉) + 오른쪽 **계획 칸 14개**(앞으로의 시간).
  - 4시간봉인 이유: 진입 조건과 판정이 4시간봉 마감 기준이다. 일봉 맥락(8월 기준봉 → 박스 → 9/21 돌파)은 세 관점 글로 전한다.

- 거래량 띠(높이 20%): 직전 20봉 평균의 2배 이상만 진하게. 두 관점 모두 거래량을 핵심으로 쓴다.

## 3. 매시간 알림과 정식 보고 구분

B 담당(AI 설계)의 권장안 (b)와 맞췄다. 매시간은 계산 엔진(코드) + 짧은 해설, 전체 분석(Opus)은 트리거 때만 한다. 트리거 이름은 B 문서 4.3절 그대로다: D 매일 09:00, S 구조 변화, P 레벨 도달, E 유효 시간 끝, V 큰 변동.

### 3.1 단계

| 종류 | 언제 | 보내는 것 | 소리 | AI 비용 |
|---|---|---|---|---|
| **조용한 알림** | 매시간 :03, 트리거 없음 | 미리보기 사진 1장 + 글 3줄. 사진 머리에 "매시간 확인 · 09:00 판단 유지" | 끔 | 없음(+ 짧은 해설) |
| **정식 보고 · 정기** | 매일 09:05(D), 유효 시간 끝(E) | 사진 + PDF | D 켬 / E는 판단이 바뀔 때만 켬 | 전체 분석 |
| **정식 보고 · 변화** | S, P(진입 구간 도착 등), V | 사진 + PDF | 판단·계획이 바뀌면 켬, 그대로면 끔 | 전체 분석 |
| **행동 알림** | 4시간봉 마감 때 진입 조건 충족 **+ 검사기 통과** / 손절·목표 가격 도달 / 무효화 | 사진 + PDF, 글 맨 앞 [행동] | 켬 | 전체 분석(확인) |
| **오류 알림** | 데이터 이상, 분석 지연(:15 넘김), 비용 한도 | 글만 | 켬(한 번만) | 없음 |

- 진입 조건이 맞아도 **검사기를 못 넘으면 행동 알림이 아니다.** 그때는 "정식 보고 · 변화"로 "조건은 맞았지만 진입 불가(이유)"를 소리 없이 알린다.
- 같은 사건은 한 번만 알린다(상태를 저장). 진입 구간 도착 알림은 계획당 1번.
- 선택 사항: 새벽(01~07시)에는 조용한 알림을 건너뛴다. 행동·오류 알림은 그대로 보낸다.
- 시스템은 주문하지 않으므로 사용자가 실제로 들어갔는지 모른다. 그래서 손절·목표 알림은 "계획을 따랐다면 79,800 도달"처럼 쓴다. 선택 사항: 텔레그램 버튼 "들어감 / 안 들어감"(기존 telegram_ui.py에 버튼 기능 있음)으로 상태를 받으면 맞춤 알림을 줄 수 있다. 지금은 모의 기록 단계이므로 이 버튼을 "모의 기록"(계획대로 했다면의 결과 기록)에 쓰는 것이 맞다.

### 3.2 메시지 예시 (텔레그램 글)

조용한 알림(10:00, **숫자는 예시** — 9/29 10시 이후 자료는 없음):
```
10:00 BTC 83,212 (1시간 −0.3%) · 판단 유지: 관망 (09:00 정식)
진입 구간 82.3~83.1k까지 −0.1% · 진행 중 4시간봉 1/4 음봉, 거래 0.6배
검사기: 진입 불가(손익비 1.4·손실 8.5%) · 다음 판정 13:00 · 유효 ~9/30 09:00
```

정식 보고 사진의 설명 글(이번 시안의 실제 값, 1024자 제한 안):
```
[정식] 9/29 09:00 BTC 83,461 — 관망 (지금은 매매 안 함)
검사기: 진입 불가 · 손익비 1.4(<2) · 손절 시 −4,300원 = 계좌 8.5%(>3%)
참고 계획: 진입 82,300~83,100 · 손절 79,800 · 목표 84,800 / 87,000
재검토: 82.3k 부근 1시간봉 자리에서 손절 폭 1.1% 이내면 다시 계산

```

행동 알림(**숫자는 예시**, a1_sizing으로 계산):
```

진입 82,350 · 손절 81,450(−1.09%) · 목표 87,000 → 손익비 4.4
0.001 BTC · 20배 격리 = 포지션 82.4 ÷ 증거금 4.12 USDT · 청산가 78,547
손절 시 −1,400원(계좌 2.9%) · 손절 없이 청산되면 최대 약 5,800원 · 주문은 직접 판단
```

### 3.3 사진과 PDF를 함께 보내는 법

1. `sendPhoto`: 미리보기 PNG + 위 설명 글. 알림 소리는 3.1절 표대로.
2. `sendDocument`: PDF를 1번 사진에 **답장**으로 붙이고 `disable_notification=true` → 알림은 한 번만 울린다.
3. 최신 정식 보고는 채팅 맨 위에 **고정**(pin)하고 이전 것은 푼다. 지금 유효한 계획을 언제나 한 번에 찾을 수 있다. 개인 채팅에서는 봇도 고정할 수 있다.

- 한 묶음(`sendMediaGroup`)으로 못 보내는 이유: 사진과 문서는 한 묶음에 섞을 수 없다.
- 사진 크기를 1080×1350(4:5)으로 정한 이유: 텔레그램은 보통 사진을 긴 변 1280px로 줄인다(고화질 설정이면 2560px). 이 크기는 거의 그대로 보인다. PDF 페이지 전체를 사진으로 보내면 크게 줄어 글자가 뭉개진다. 그래서 사진은 따로 설계했다.
  - 사진에 들어가는 것: 판단(큰 글자), 세 관점 한 줄, 검사기 결과·재검토, 검증 상태, 차트. 번호 표시는 넣지 않는다.
  - 진입 불가일 때는 계획 타일을 사진에서 뺐다. 지시처럼 읽히지 않게 하려는 것이고, 계획 가격은 차트 오른쪽에 "참고 계획"으로만 보인다.
- 휴대폰 알림에는 설명 글 앞부분이 보이므로 **첫 줄에 판단, 둘째 줄에 검사기 결과**를 둔다.
- 크기: PDF 약 90KB, 사진 약 180KB. 그리는 시간 약 5초(데이터 읽기 포함).
- 다른 방법(선택): 매시간 새 메시지 대신 고정 메시지 1개를 매시간 고쳐 쓰기(`editMessageMedia`). 채팅은 깨끗하지만 "매시간 받는다"는 느낌은 약하다.

### 3.4 1시간 타이밍 표시

- 매시간 사진에는 지금 만들어지는 4시간봉을 1시간봉으로 쌓아 **속이 빈 캔들**(테두리만)로 그린다. 옆에 "진행 1/4 · 13:00 마감".
- 진입 조건을 3칸 체크로 보여 준다: 구간 도착 / 양봉 마감 / 거래 증가. 판정은 4시간봉이 마감될 때만 한다(01·05·09·13·17·21시).
- 재검토 조건(1시간봉 자리)은 매시간 엔진이 확인한다: 82.3k 부근에서 확정된 1시간봉 스윙 저점 기준 손절 폭 ≤ 약 1.1%이면 a1_sizing으로 다시 계산해 검사기에 넣는다.
- 시안(09:00)은 막 4시간봉이 마감된 시각이라 진행 중 캔들이 없다. 그래서 "지금 09:00 / 다음 판정 13:00"만 보인다.

## 4. 디자인 선택 이유 (짧게)

- **결론 먼저, 규칙 결과 먼저**: 휴대폰 첫 화면에 "무엇을 할지(관망)·검사기 결과·검증 상태·잃을 수 있는 돈·언제 다시 볼지"가 보여야 한다. 근거는 밀어서 본다.
- **잃을 돈을 원화로, 계좌 대비 %와 함께**: 초보에게 가장 중요한 숫자. 상한을 넘으면 노란 띠로 경고한다(상태 색은 아이콘·글자와 함께만 쓴다).
- **레버리지는 손실 금액 옆에만**: "13배"를 따로 크게 쓰면 위험이 13배처럼 읽힌다. "포지션 ÷ 증거금"과 "잃는 돈은 손절이 정함"을 같이 쓴다(A1 §8.4).
- **한국식 색을 끝까지 같은 뜻으로**: 빨강 = 오름·이익(양봉, 목표 쪽 영역, 목표 타일), 파랑 = 내림·손실(음봉, 손절 쪽 영역, 손절 타일). "진입 불가"는 빨강을 쓰지 않고 진회색 칩으로 표시한다(빨강은 이 보고서에서 "오름"이라서).
- **모양 + 번호 + 글자**로 관점 구분. 색약 검사기로 확인했다(2절).
- **번호는 8개 이하, 차트 위 글은 짧은 꼬리표만**: 글자가 많으면 휴대폰에서 아무것도 안 읽힌다.
- **글자 겹침 자동 검사**: 스크립트가 글자·배지·캔들이 겹치거나 그림 밖으로 잘리는지 매번 검사한다(시안 0건). 칸에 안 들어가는 글은 자동으로 줄이고, 칸을 넘치면 멈춘다(assert).
- **숫자는 코드가 계산**: 수량·레버리지·청산가·원화 손실은 AI가 아니라 a1_sizing이 낸다(B 문서와 같은 원칙). AI는 판단과 표시 목록(marks)만 준다.

## 5. 시안 숫자의 근거 (a1_sizing.py로 계산)

- 데이터: 바이낸스 4시간봉, 마지막 봉 9/29 05:00~09:00 KST(마감된 봉만 사용). 종가 83,461. 9/20 저점 80,095.9(9/20 09시 봉). 4시간 ATR(14) 770.
- 손절 79,800: 9/20 저점보다 296 아래(약 0.38 ATR). 8만 달러 어림수보다도 아래(손절이 몰리는 자리를 피함).
- 계좌 E = 50,000 ÷ 1,400 = 35.71 USDT. 최소 주문 50 USDT → 50 ÷ 82,700 = 0.0006 → 수량 단위 0.001로 올림 → **0.001 BTC**(82.7 USDT).
- 1 BTC당 손절 손실 u = 2,900 + 82,700 × 0.07%(진입 테이커+슬리피지) 57.9 + 79,800 × 0.07%(손절) 55.9 + 펀딩 82,700 × 0.01% × 36/8 = 37.2 → 3,051.
- 손절 시 손실 = 0.001 × 3,051 = **3.05 USDT ≈ 4,271원 → 약 4,300원 = 계좌의 8.5%**. 상한 3% = 1.07 USDT ≈ 1,500원 → 2.8배.
- 목표2 이익 = 0.001 × (4,300 − 57.9 − 87,000 × 0.02%(지정가) 17.4 − 37.2) = 4.19 USDT → **손익비 1.37**. 목표1은 1.99 USDT → 0.65.
- 레버리지: 손절 거리 d = 3.51% → 필요한 청산 거리 = max(2 × 3.51%, 3.51% + 3%) = 7.01% → 롱 최대 ⌊1 ÷ (0.004 + 0.996 × 0.0701)⌋ = **13배**(상한 20배 안). 주문에 필요한 최소는 3배.
- 증거금 = 82.7 ÷ 13 = **6.36 USDT**(손절 실패 때 최대 손실, 약 8,900원). 청산가 = (82.7 − 6.36) ÷ (0.001 × 0.996) = **76,645**(진입가에서 7.3%, 손절 거리의 2.1배). 실질 레버리지 82.7 ÷ 35.71 = 2.3배.
- 판정: a1_sizing `NO_TRADE(최소 수량 강제 위험 8.5% > 상한 3%)` + 손익비 1.37 < 2 → **진입 불가**.
- 재검토 조건: 82,300 진입에서 위험 3% 이내가 되는 최대 손절 폭을 이분 탐색(1시간봉 자리라 보유 12시간) → 1.15% → 손절 81,356 이상(시안은 10원 단위로 올려 81,360). 그때 20배, 위험 2.99%, 손익비(목표2) 4.3.
- 지금 가격(83,461)에서 사면: 목표까지 3,539 < 손절까지 3,661 → [CP-25-3]에 따라 진입하지 않는다.

## 6. 확인 필요·한계

- 최소 주문 50 USDT·수량 단위 0.001 BTC·유지증거금률 0.4%는 퀀트① 확인값(뉴스 3곳 + 거래소 정보 스냅샷)이다. 실제 운영 맥에서 `GET /fapi/v1/exchangeInfo`로 한 번 더 확인하고, 하루 한 번 갱신한다.
- 0.001 BTC는 나눌 수 없어 **분할 진입·분할 익절이 안 된다**. 그래서 목표1은 "닿으면 손절을 본전으로"로 바꿨다. 청산(감소 전용) 주문은 최소 금액 규칙이 적용되지 않는다는 검색 요약이 있다(A1 §1).
- 청산가는 근사식이다. 거래소 확인 창의 값이 우선이다.
- 진입 조건의 "거래 증가" 기준(예: 직전 20봉 평균의 1.5배)은 전략 담당이 숫자로 고정해야 한다.
- 손익비 정의: 시안은 a1_sizing과 같이 "진입가 82,700 가정, 비용 뺀 값"이다. B 문서 V10은 "진입 구간의 가장 불리한 끝(83,100)"으로 재자고 한다. 그 기준이면 손익비는 더 낮다(약 1.1). 팀에서 하나로 정해야 한다.
- 세 관점 판단 방식은 과거 성과 검증 전이다(검증 상태 줄로 표시).
- 페이지가 길어졌다(세로/가로 약 3.0). 휴대폰 첫 화면에 차트가 안 들어온다. 검사기·검증 상태 줄이 들어간 대가다. 줄이려면 수량 칸 설명을 짧게 하거나, 진입 불가일 때 참고 계획을 차트 아래로 내리는 배치를 쓸 수 있다(1.1절).
- 글자 크기: 휴대폰 폭에 맞추면 본문 약 9px, 작은 메모 약 8px, 핵심 숫자 15px 이상.
- 실제로 돌릴 컴퓨터에도 Pretendard 글꼴 파일이 필요하다(무료 OFL). 없으면 한글이 깨지므로 시작할 때 확인하고, 없으면 멈추게 한다.

## 7. 실서비스로 옮길 때 (구현 메모)

- 입력은 3가지다. ① 엔진 사실표(가격·레벨) ② AI JSON(판단, 계획 레벨, marks 8개 이하, 관점별 3줄 이하·줄당 40자 이하, 규칙 번호) ③ 프로그램 계산(a1_sizing: 수량·레버리지·증거금·청산가·원화, 검사기 판정, 재검토 조건). 렌더러는 ①③의 숫자만 쓰고, ②에서는 글과 위치만 받는다.
- 검사기 결과가 "진입 불가"면: 칩은 관망, 검사기 칸에 미달 항목과 재검토 조건, 참고 계획 제목, 사진에서는 계획 타일 생략. "통과"면 검사기 칸을 "검사기 통과: 진입 검토 가능"으로 바꾸고 사진에 계획 타일을 넣는다.
- marks 종류는 시안에서 쓴 것으로 충분하다: candle(봉 화살표), level(점선), band(띠), zone(워뇨띠 구간), highs(고점 묶음), plan(진입·손절·목표).
- 배치 규칙: 꼬리표가 겹치면 빼고 배지만 남긴다. 배지끼리 겹치면 위·아래로 옮긴다. 그래도 겹치면 경고를 내고 보낸다(보고가 늦는 것보다 낫다).
- 위험 띠 규칙: 손절 손실이 이 단계 상한(5만 원 단계 3%)을 넘으면 노란 경고 띠(상한의 몇 배인지 + 이유). 넘지 않으면 회색 띠에 "손절 시 약 ○원(계좌 ○%)"만 쓴다.
- 시안 코드는 연구용이다. bot/ 아래로 옮길 때 테스트(겹침 0건, 글꼴 내장, 1페이지, a1_sizing 값과 표시 값 일치)를 함께 만든다.
