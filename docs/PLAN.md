# BTC/USDT 선물 시그널 & 반자동 매매 시스템 — 기획서 v0.1

> 작성일: 2026-09-29 · 상태: 초안 (결정 필요 항목은 ❓ 표시)

## 1. 한 줄 요약

Claude가 BTC/USDT 차트(캔들·거래량·이동평균선)를 분석해서 **텔레그램으로 보고**하면,
사람이 검토한 뒤 **[롱] / [숏] / [패스] 버튼**을 눌러 **바이낸스 선물 주문**을 실행하는 반자동 매매 시스템.

- 판단은 사람, 분석과 실행은 시스템이 한다 (Human-in-the-loop)
- 완전 자동매매가 아니므로 AI 오판이 곧바로 손실로 이어지지 않는다

## 2. 전체 흐름

```
[스케줄러] 캔들 마감 시점마다 (예: 1시간봉 마감)
     │
     ▼
[① 데이터 수집]  거래소 공개 API → 캔들(OHLCV) 조회  ※ 조회에는 API 키 불필요
     │
     ▼
[② 지표 계산]    이동평균선(MA 20/60/120), 거래량 평균 등 + 차트 이미지 생성
     │
     ▼
[③ Claude 분석]  숫자 데이터 + 차트 이미지 → 정해진 형식(JSON)으로 결과 반환
     │           (방향 / 근거 / 진입가 / 손절가 / 익절가 / 확신도)
     ▼
[④ 텔레그램 알림] 분석 요약 + 차트 이미지 + [롱] [숏] [패스] 버튼
     │
     ▼  사람이 검토 후 버튼 클릭
[⑤ 확인 단계]    "롱 0.01 BTC, 레버리지 3x, 손절 xxx 맞습니까?" [확인] [취소]
     │
     ▼
[⑥ 리스크 검사]  한도 초과·유효시간 만료·중복 클릭이면 차단
     │
     ▼
[⑦ 주문 실행]    거래소 API로 진입 주문 + 손절/익절 주문을 함께 등록
     │
     ▼
[⑧ 결과 보고]    체결 결과를 텔레그램으로 전송 + 전 과정 기록(감사 로그)
```

## 3. 주요 결정 사항

### 3.1 알림 채널: **텔레그램** (Slack 대신) ✅ 추천

| 항목 | 텔레그램 | Slack |
|---|---|---|
| 버튼(인라인 키보드) | 기본 지원, 간단함 | 가능하지만 외부 공개 서버(HTTPS) 필요 |
| 모바일 사용성 | 좋음 | 보통 |
| 개인 용도 | 적합 | 팀 협업용에 가까움 |
| 서버 구조 | 봇이 텔레그램에 먼저 접속(폴링) → **외부에 포트를 열 필요 없음** | 인바운드 웹훅 수신 필요 |

→ 보안 측면에서도 **인바운드 포트를 열지 않아도 되는 텔레그램 폴링 방식**이 유리하다.

### 3.2 거래소: **바이낸스로 시작하되, 교체 가능하게 설계** ✅ 추천

- 선물 거래량 1위권, 유동성 풍부, **선물 테스트넷(모의거래) 제공** → 개발 단계에 필수
- **ccxt 라이브러리**로 거래소를 추상화 → 나중에 Bybit, OKX 등으로 바꿀 때 설정만 교체
- ❓ 한국 거주자의 해외 거래소 이용과 관련된 규제·세금은 직접 최신 상황을 확인할 것

### 3.3 분석 주기 ❓

| 옵션 | 알림 빈도 | 특징 |
|---|---|---|
| 15분봉 | 하루 최대 96회 | 너무 잦음, 피로도 높음 |
| **1시간봉** (추천 시작점) | 하루 최대 24회 | 적당함 |
| 4시간봉 | 하루 최대 6회 | 스윙 트레이딩에 적합, 신호 질이 좋은 편 |

- 추가 옵션: **"관망(중립)"이면 알림을 생략**하고, 의미 있는 신호일 때만 보내기

## 4. 보안 설계 (핵심)

돈이 걸린 시스템이므로 **보안과 리스크 관리를 기능보다 먼저** 설계한다.

### 4.1 API 키 관리
- 거래소 API 키 권한: **선물 거래만 허용, 출금 권한은 절대 금지**
- **IP 화이트리스트**: 배포 서버의 고정 IP에서만 API 키 사용 가능
- 키는 코드나 GitHub에 절대 넣지 않음 → `.env` 파일(`.gitignore` 처리) 또는 서버의 Secret 관리 기능 사용
- 개발 단계에서는 **테스트넷 키만** 사용

### 4.2 텔레그램 버튼 보안
- **허용된 사용자 ID(본인)만** 버튼을 실행할 수 있음 (화이트리스트). 다른 사람 클릭은 무시하고 기록
- **신호 유효시간**: 예) 15분이 지난 신호의 버튼은 만료 처리 (시세가 이미 바뀜)
- **1회성 처리**: 같은 신호는 한 번만 주문 (중복 클릭·재전송 방지)
- **2단계 확인**: 버튼 → 주문 내용 확인 → [확인]을 눌러야 실행

### 4.3 리스크 한도 (코드로 강제)
- 최대 레버리지 (예: 3배) ❓
- 1회 최대 주문 금액 / 최대 보유 포지션 ❓
- **손절 주문 필수**: 손절 없이는 진입 불가
- **일일 손실 한도**: 초과하면 당일 주문 자동 차단 ❓
- **긴급 정지(Kill switch)**: 텔레그램 `/stop` 명령 → 신규 주문 중단
- 격리 마진(Isolated) 사용 → 손실이 해당 포지션 안에서만 발생

### 4.4 감사 로그
- 분석 결과, 버튼 클릭(누가, 언제), 주문 요청과 응답, 에러를 모두 DB에 기록

## 5. 기술 스택 (추천)

| 구성 | 선택 | 이유 |
|---|---|---|
| 언어 | Python | 초보자 친화적, 금융·데이터 라이브러리 풍부 |
| 거래소 연동 | ccxt | 거래소 교체가 쉬움 |
| 데이터·지표 | pandas | 표 형태 데이터 처리의 표준 |
| 차트 이미지 | mplfinance | 캔들 차트 이미지 생성 |
| AI 분석 | Anthropic Claude API | 차트 이미지 해석 + 구조화된 결과(JSON) |
| 텔레그램 | python-telegram-bot | 버튼 지원, 문서 풍부 |
| 스케줄링 | APScheduler | 캔들 마감 시점마다 실행 |
| 저장소 | SQLite | 설치 불필요한 파일 DB, 개인용으로 충분 |
| 배포 | Docker + 클라우드 서버(VPS) 1대 | 24시간 가동, 고정 IP |

※ Claude API는 claude.ai 구독과 **별도**로 API 키를 발급받고 사용량만큼 과금된다.

## 6. 개발 단계 (로드맵)

각 단계가 끝날 때마다 PR로 올리고, 검토한 뒤 main에 합친다.

| 단계 | 내용 | 배우는 개념 | 돈 위험 |
|---|---|---|---|
| **0. 준비** | 계정 발급 (텔레그램 봇, 바이낸스 테스트넷, Anthropic API) | API, API 키, 환경변수 | 없음 |
| **1. 데이터** | 캔들 조회 + 이동평균·거래량 계산 + 차트 이미지 생성 | Python 기초, 라이브러리, 데이터프레임 | 없음 |
| **2. 분석** | Claude에 데이터와 차트를 보내고 JSON 결과 받기 | 프롬프트 설계, JSON | 없음 |
| **3. 알림** | 텔레그램으로 분석 결과 + 버튼 전송 | 봇, 이벤트 처리 | 없음 |
| **4. 모의주문** | 버튼 → **테스트넷** 주문 (손절·익절 포함) | 주문 유형, 에러 처리 | 없음 (가상 자금) |
| **5. 리스크** | 한도, 유효시간, 중복 방지, 긴급 정지, 감사 로그 | 방어적 설계, DB | 없음 |
| **6. 배포** | Docker로 서버에 24시간 가동 | 서버, Docker, 로그 | 없음 |
| **7. 검증** | 테스트넷에서 1~2주 운영하며 신호 품질 기록 | 성과 측정 | 없음 |
| **8. 실거래** | **소액**으로 실거래 전환 | — | ⚠️ 있음 |

## 7. 결정이 필요한 항목 (❓)

1. 분석 주기: 1시간봉 / 4시간봉 / 기타
2. 중립(관망) 신호도 알림을 받을지
3. 최대 레버리지, 1회 주문 금액, 일일 손실 한도
4. 손절·익절 가격: Claude 제안값 사용 / 고정 비율(예: -2% / +4%) 사용
5. 이동평균선 기간: 20·60·120 (기본값 제안)

## 8. 면책

이 시스템은 개인 학습과 보조 도구 용도다. AI 분석은 틀릴 수 있으며, 레버리지 선물 거래는 원금 이상의 손실 위험이 있다.
