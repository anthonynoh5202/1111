## 0. 3분 요약 (먼저 읽기)

1. **새로 사야 하는 것은 거의 없다.** 이미 있는 폰, 집 PC(없으면 5단계 전에 준비), 클라우드 서버 1대(월 $12), Claude API(월 $10~18)가 전부다. 나머지 소프트웨어는 모두 무료 오픈소스다.
   - **서버는 1단계 후반에 거래 키 없이 만드는 것이 기본이다.** 코드 규칙 전향 모의 기록(A6)과 OI·롱숏비 수집이 24시간 돌아야 하기 때문이다. OI·롱숏비는 거래소 API가 최근 30일만 주므로, 서버가 늦게 생기면 그 기간의 데이터를 다시 받을 수 없다 [판정 A6, Q16] [02 요약 3] (INFRA §2.4, ARCHITECTURE §1.3).
2. **봇에 들어가는 외부 파이썬 패키지는 6개다.** ccxt · pandas · anthropic · python-telegram-bot[job-queue] · pydantic-settings · matplotlib이다. 이 목록(허용목록)에 없는 패키지가 들어오면 자동 검사(CI)가 실패하도록 만든다 [판정 SEC-06].
3. **코드보다 계정 설정이 먼저다.** 이메일 → 비밀번호 관리자 → GitHub → Anthropic → 텔레그램 → AWS → 바이낸스 순서로 2단계 인증을 켠다. 2단계 인증은 문자(SMS) 말고 보안키나 인증 앱으로 한다 [판정 SEC-03].
4. **새로 확인한 사실 (PLAN §6.4·D15 보완 필요).** 개인 계정이 가진 **비공개** 저장소에서는 GitHub의 비밀 유출 검사(Secret scanning)와 푸시 차단(push protection)을 켤 수 없다. 브랜치 보호와 CODEOWNERS는 **유료 GitHub Pro**가 있어야 쓸 수 있다 [S4][S5][S6][S7][직접].
   - 비공개 전환 권고는 그대로 둔다. 비밀 유출 방어는 **gitleaks(커밋 전 + CI)**가 주 통제가 된다.
   - GitHub Pro 구독 여부는 **[결정 필요]**다(§12 #2).
5. **거래소 키는 필요한 때, 필요한 곳에서만 만든다.**
   - 테스트넷 키는 4단계, 실거래 키는 6단계 직전에 만든다. 둘 다 운영 서버의 비밀 파일에만 둔다.
   - Claude Code 클라우드 세션에는 테스트넷을 포함해 **어떤 거래소 키도 넣지 않는다** (D15).
6. **월 고정비는 약 $23~31(약 3.2만~4.3만 원)이다** (D19, **[결정 필요]**). Claude Code 구독, GitHub Pro(선택), 보안키(선택)는 별도이며 가격은 확인 필요다.

### 0.1 용어 풀이 (처음 나오는 전문 용어)

| 용어 | 한 줄 설명 |
|---|---|
| 패키지(라이브러리) | 남이 만들어 공개한 코드 묶음. `pip`나 `uv`로 내려받아 쓴다 |
| 의존성 | 어떤 패키지가 돌아가려고 함께 설치하는 다른 패키지 |
| 락파일 (`uv.lock`) | 설치된 모든 패키지의 정확한 버전과 파일 지문(해시)을 적어 둔 파일. 어디서 설치해도 똑같이 재현된다 |
| 공급망 공격 | 내가 쓰는 패키지에 악성 코드를 심어 나를 공격하는 방식 |
| 허용목록 | "이 목록에 있는 것만 허용"하는 방식. 목록 밖은 모두 거부한다 |
| CI | 코드를 올릴 때마다 자동으로 테스트·검사를 돌리는 장치. 여기서는 GitHub Actions |
| 컨테이너 / Docker | 프로그램과 필요한 부품을 한 상자(이미지)에 담아 어디서나 똑같이 실행하는 기술 |
| 비밀(secret) | API 키, 봇 토큰, 개인키처럼 남에게 보이면 안 되는 값 |
| 2단계 인증 / TOTP / 보안키 | 비밀번호 외에 두 번째 증거를 요구하는 로그인 방식 / 인증 앱이 30초마다 바꿔 보여 주는 6자리 숫자 / USB·NFC로 꽂거나 대는 작은 인증 장치(FIDO2·패스키) |
| 서브계정 | 한 사람 명의 아래 잔고와 키를 분리한 하위 계정 |
| 테스트넷 / 데모 트레이딩 | 가짜 돈으로 주문을 시험하는 거래소 환경 |
| IP 화이트리스트 | 등록한 인터넷 주소(IP)에서 온 요청만 받는 설정 |
| Ed25519 | 내가 만든 개인키로 서명하고 거래소에는 공개키만 주는 서명 방식. 거래소 쪽에서 정보가 새도 서명을 위조할 수 없다 |
| 데드맨 스위치 | 봇이 주기적으로 "살아 있음" 신호를 보내다가 끊기면 외부 서비스가 경보를 보내는 장치 |
| 백테스트 / 페이퍼 | 과거 데이터로 규칙을 모의 실행하는 것 / 실시간 시세로 돈 없이 모의 운영하는 것 |
| 전향 모의 기록 (A6, FWD_SHADOW) | 규칙을 고정한 날 이후의 실시간 봉에 코드 규칙만 적용해 "그때 진입했다면"을 기록하는 것. 과거 데이터로 맞춘 결과가 아니라서 진짜 검증 자료가 된다 |
| 안전 상태 | 열린 포지션 0, 미체결 주문 0, 승인 대기 신호 0인 상태. 배포·재부팅·키 교체는 이 상태에서만 한다 (INFRA §0.1) |

### 2.2 계정별 보안 설정

#### (1) 이메일 — 모든 것의 뿌리
- 2단계 인증을 **SMS가 아닌 방식**으로 켠다(보안키 또는 인증 앱). 지원 방식은 쓰는 메일 서비스에서 확인한다(확인 필요).
- 복구 코드는 오프라인 비밀번호 관리자와 종이 사본 두 곳에 둔다.
- 폰 이메일 앱의 알림을 켠다. healthchecks와 독립 감시자의 경보가 이 경로로 온다. 텔레그램이 의심스러울 때의 **유일한 독립 경보 경로**다 [07 §2.4].

#### (2) 오프라인 비밀번호 관리자
- 예: **KeePassXC**(PC용, GPL-3.0, 인터넷 동기화 없이 암호화 파일 하나로 동작) [S23]. 다른 제품을 써도 된다. 조건은 두 가지다: 오프라인 파일이고, 강한 마스터 비밀번호로 암호화한다.
- 담는 것:
  - 모든 계정 비밀번호와 2단계 인증 복구 코드
  - 봇 토큰, Anthropic 키 원본
  - age 백업 복호화 개인키 (ARCHITECTURE C17. **서버에는 두지 않는다**)
  - 거래소 Ed25519 개인키 원본 (D15). 선택지(제안): 거래소 키는 재발급이 쉬우므로 원본을 보관하지 않고 "재발급 절차"만 적어 두는 방법도 있다. SECURITY.md에서 정한다
- 암호화 파일 사본을 USB 등 **두 곳**에 둔다. 폰에는 두지 않는 것을 권한다(제안). 폰 하나에 권한이 몰리는 것을 피하기 위해서다 [판정 SEC-03].

#### (3) 통신사 — 유심 보호

- **보안키 구매는 [결정 필요]**다(§12 #5). 주 키와 예비 키 2개를 권한다. 가격은 확인 필요다.
- 보안키가 없으면 인증 앱을 **폰이 아닌 기기**에 둔다. 폰 하나를 잃었을 때 텔레그램·SSH·거래소 로그인이 한꺼번에 넘어가는 것을 막기 위해서다 [판정 SEC-03].

### 2.4 비밀(키·토큰) 목록 — 어디서 만들고 어디에 두나

**공통 원칙** (D15):
- Git·채팅·스크린샷·Claude 대화에 넣지 않는다.
- **환경 변수로 넘기지 않는다.** Docker 문서는 환경 변수가 모든 프로세스에 보이고 로그에 찍힐 수 있다고 경고한다. Compose secrets는 `/run/secrets/<이름>` 파일로, **서비스별로** 마운트한다 [S13][직접].
- 설정 로더 pydantic-settings는 비밀 파일 폴더(`secrets_dir`)를 읽을 수 있다. 다만 **환경 변수와 dotenv가 비밀 파일보다 우선**한다. 그래서 비밀 필드는 비밀 파일에서만 읽도록 소스를 좁힌다. 또 비밀 폴더가 없으면 **경고만 하고 넘어가므로**, 비밀 필드는 기본값 없는 필수 항목으로 선언해 없으면 시작이 실패하게 한다 [S14][직접].

### 5.6 버전 고정과 업데이트 규칙 [확정 권고, D9]

| 규칙 | 내용 | 근거 |
|---|---|---|
| Python | **3.14로 고정**(`.python-version`). 3.15(2026-10-01 출시 예정)는 numba·TA-Lib·aiogram·vectorbt 등이 아직 지원하지 않아 최소 6개월 보류한다. freqtrade 공식 이미지도 3.14.7을 쓴다 | [06 §2.1] |
| 락파일 | `uv.lock`을 커밋한다. 설치는 `uv sync --locked`로 한다. 락파일이 최신이 아니면 갱신하지 않고 **오류를 낸다** | [S3][직접] |
| 쿨다운 | `exclude-newer = "7 days"`. 올라온 지 7일이 안 된 배포 파일은 없는 것으로 친다. 기준 시각은 락파일에 기록되고, `--upgrade` 같은 새 해석 때만 바뀐다. uv 문서도 이 기능을 "커뮤니티가 새 버전을 검증할 시간을 벌어 보안을 높이는 방법"이라고 설명한다 | [S2][직접] |
| 긴급 보안 패치 | 7일을 기다릴 수 없으면 패키지별 예외(`exclude-newer-package`)를 PR로 추가하고 이유를 적는다 | [S2][직접] |
| 해시 | uv 문서는 해시가 락파일과 내보낸 파일에 남는다고 적는다. **설치 때 해시를 검증하는 동작은 1단계에서 확인**한다 | [S2][직접], [06 §3.4-5] |
| 정기 업데이트 | 월 1회 의도적으로 한다. pip-audit 경보가 오면 바로 검토한다 | [06 §3.3-1] |
| ccxt 갱신 | 올릴 때마다 테스트넷·데모에서 "진입 → 손절 → 청산" 회귀 시험을 한다. 바이낸스 조건부 주문이 2025-12-09 Algo 주소로 옮겨졌을 때 freqtrade의 손절이 실패한 사례가 있다(-4120) | [04 §3.3-5], [05 §2.2.1] |
| Docker 이미지 | 베이스 이미지는 태그가 아니라 digest로 고정한다 | D12 |
| GitHub Actions | 외부 액션은 **전체 커밋 SHA로 고정**한다. GitHub 문서도 이것이 액션을 불변으로 쓰는 유일한 방법이라고 적는다 | [S12][직접] |

### 5.7 새 패키지 도입 체크리스트

[06 §3.3-2]의 목록에 이름 확인과 절차를 더했다.

1. **이름이 정확한가.** AI가 존재하지 않는 패키지 이름을 지어낼 수 있다(slopsquatting). 이름이 비슷한 다른 패키지도 있다.
   - 예: PyPI의 `sops`는 2018-11-28에 나온 1.18 버전으로 멈춰 있다 [S26][직접]. 지금 쓰는 sops(Go 실행 파일)가 아니다.
2. 소스 저장소가 공개돼 있고 PyPI와 연결돼 있는가
3. 최근 12개월 안에 릴리스가 있는가
4. 관리자가 바뀌었거나 릴리스 이력이 지워지지 않았는가. 반례는 pandas-ta다: 원 저장소 404, 이력 삭제, 관리 주체 변경 [06 §2.4.1]
5. 라이선스가 명시돼 있는가
6. Python 3.14용 설치 파일(휠)이 있는가
7. 끌고 오는 의존성이 몇 개인가
8. 허용목록 PR에 도입 이유를 적고, **별도 Claude 리뷰 세션**이 검토했는가 [판정 SEC-06]

### 5.8 Claude에게 코드를 요청할 때 명시할 것 (바이브코딩 주의)

Claude가 학습한 예제는 옛 버전 기준일 수 있다(추정). 요청할 때 다음을 적는다.
- "Python 3.14, **pandas 3.0 기준**": 문자열 타입, Copy-on-Write, 날짜 해상도가 바뀌었다 [06 §2.4.2]
- "**anthropic 1.x**, 모델 `claude-opus-5-5`, effort 명시(기본 medium), `output_config.format`으로 JSON 스키마 강제" [S24]
  - Opus 5.5는 thinking을 끌 수 없다. 강제 도구 선택(`tool_choice` any/tool)은 400 오류가 난다. assistant 프리필도 안 된다. temperature를 기본값 외로 주면 400이다. 그래서 JSON은 구조화 출력으로 받는다 [S24], [03 §1]
  - SDK는 기본으로 2번 재시도하고 **타임아웃도 재시도**한다. 그래서 최악의 대기 시간은 타임아웃 × (재시도 + 1)이다. 타임아웃 120초(D2)면 최대 6분이다. 재시도 횟수를 설정에 명시한다(제안, ARCHITECTURE C7과 조율) [S24]
  - `fallbacks`는 켜되, 폴백 모델이 답하면 승인 버튼을 만들지 않고, 실제 응답 모델 ID를 저장한다 [판정 SEC-11]
- "python-telegram-bot 22 (비동기), 롱 폴링, `allowed_updates = [message, callback_query]`" [07 §2.1–2.2]
- "ccxt 4.5, 바이낸스 USDⓈ-M, algo 조건부 주문" [08 §2.5]

## 6. 백테스트·분석 도구

### 6.1 구성 (ARCHITECTURE C19와 같음)

| 부품 | 무엇으로 | 역할 |
|---|---|---|
| **재생기** | 우리 공용 모듈(특징 계산·규칙 엔진·상태 머신·리스크 가드·채점기). 새 패키지 없음 | **G1 판정의 기준.** 과거 봉을 한 개씩 재생해 공용 체결 모델(지연 L + 관통 체결 + GTD 만료 + 비용)로 채점한다 [판정 Q6] |
| **freqtrade** | 별도 Docker | 교차 검증. 누수 점검(`lookahead-analysis`·`recursive-analysis`) [06 §2.5], 수수료·펀딩·격리 처리 대조, 일봉 돈치안 앙상블 기준선 [판정 Q15+A3] |
| 통계 | numpy (+ 선택 scipy) | 부트스트랩 95% 하한, 무작위 진입 기준선 순열 검정, DSR·PBO [08 §2.8] |
| 시도 레지스트리 | SQLite 또는 CSV | 시도한 모든 변형을 기록한다. DSR·PBO의 입력이다 [판정 Q14] |
| 그림 | matplotlib | 결과 보고서의 그래프 |

- **주의**: freqtrade의 기본 가정은 우리 체결 모델과 다르다. freqtrade는 다음 봉 시가에 진입하고, 봉 범위 안이면 슬리피지 없이 요청가에 체결되고, 손절도 정확히 손절가에 체결된다고 본다 [06 §2.5]. 콜백(`custom_entry_price` 등)으로 어디까지 재현할지는 2단계에서 확인한다. 두 결과가 크게 다르면 원인을 찾기 전에는 G1을 판정하지 않는다 [ARCHITECTURE C19].
- Claude가 들어간 판단은 과거 백테스트를 하지 않는다. 학습 데이터 마감(2026-06) 때문에 룩어헤드가 생긴다. 전향 기록으로만 평가한다 [03 §2.3].

### 7.2 GitHub 요금제 제약과 대응 (새로 확인)

PLAN §6.4와 D15는 "저장소 비공개 + Secret scanning + push protection + main 브랜치 보호"를 함께 적었다. 하지만 **개인 계정의 비공개 저장소에서는 이 조합이 성립하지 않는다** (§2.2-4 표) [S4]~[S7][직접]. 비공개 권고는 유지하고, 다음으로 보완한다.

| 원래 의도 | 비공개 + Free에서의 대응 | 비공개 + Pro에서의 대응 |
|---|---|---|
| 비밀이 저장소에 들어가지 않게 | **gitleaks를 커밋 전 + CI에서 실행**(주 통제). `.gitignore` 기본 거부. PR 수용 시험에 "가짜 키를 커밋하면 막힌다"를 넣는다 | 같음 (Pro로도 Secret scanning은 안 된다) |
| CI가 실패한 코드는 병합되지 않게 | 강제할 수 없다. 사람이 CI 녹색을 확인하고 병합하는 규칙뿐이다. 보완(제안): `deploy.sh`가 태그 커밋의 CI 성공을 확인한 뒤에만 배포한다(읽기 토큰이 하나 더 필요하다. INFRA.md에서 판단) | **브랜치 보호로 "CI 통과 필수"를 강제한다** |
| 가드·불변조건 테스트·허용목록 파일 보호 | CODEOWNERS를 쓸 수 없다. 규칙: 이 파일들이 바뀌는 PR에는 별도 Claude 리뷰 세션의 결과를 붙인다. CI가 보호 파일 변경을 PR에 표시한다(제안) | CODEOWNERS로 지정한다. 다만 혼자 쓰는 저장소에서 "리뷰 필수"를 켜면 본인 PR을 본인이 승인할 수 있는지에 따라 병합이 막힐 수 있다(**확인 필요**). "CI 통과 필수" 위주로 설정한다 |

- **권고**: 비공개로 전환하면 **GitHub Pro를 구독**한다(§12 #2, 가격 확인 필요). 이유: 코드를 읽지 못하는 사용자에게 "CI가 실패하면 병합이 안 된다"는 강제 장치가 가장 싸고 확실한 안전망이다 [판정 SEC-06+F09].
- 공개 유지(PLAN §11 #8 (b))를 택하면 Secret scanning(자동), 사용자 단위 push protection(기본 켜짐), 브랜치 보호, CODEOWNERS를 모두 무료로 쓸 수 있다 [S4]~[S7]. 대신 설정·계정 ID·RUNBOOK을 별도 비공개 저장소나 서버에만 두는 "공개 전제 설계"가 필요하다 (PLAN §8.1).

| 세금 | 2027년 거래분부터 과세 가능. 국회 최종 의결 전이다(검색 요약) | PLAN §8.7 |

### 9.4 언제부터 돈이 드나 (추정)

| 단계 | 월 비용 | 이유 |
|---|---|---|
| 0 ~ 1단계 전반 (준비·데이터 코드 작성) | $0 | 개발은 클라우드 세션. 서버가 아직 없다 |
| **1단계 후반 ~ 2단계** (서버 구축·24시간 수집·전향 기록·G1) | **약 $13** (서버 $12 + 백업·스냅샷 약 $1, 추정). 1GB면 약 $8. 신규 가입자 첫 3개월 무료는 검색 요약 | 서버가 1단계 후반부터 24시간 돈다(기본). Claude API는 아직 부르지 않는다(30분 점검의 짧은 호출은 몇 센트 이하, 추정). 백테스트는 집 PC |
| 3~5 (섀도·페이퍼·테스트넷·운영 강화) | 약 $23~31 | 서버 + 백업 + Claude API |

## 10. 초보자용 설치·준비 순서

표시: **[나]** = 사용자가 폰·PC 설정 화면에서 직접 · **[Claude]** = 클라우드 세션이 PR로 만든다 · **[서버]** = 사람이 SSH로 접속해 Claude가 써 준 스크립트나 명령 한 줄을 실행한다.
단계 번호와 기간은 PLAN §7.1을 따른다. 기간은 모두 추정이다.

### 0단계 — 준비·게이트 (1~2주, 설치할 코드 없음)

2. **[나]** 집 PC에 오프라인 비밀번호 관리자를 설치한다. 1번 복구 코드부터 넣는다.
3. **[나]** 보안키 구매 여부를 정한다(§12 #5). 사지 않으면 인증 앱을 폰이 아닌 기기에 설치한다.
4. **[나]** 통신사 유심 보호 서비스를 신청한다(이름 확인 필요).
5. **[나]** GitHub:
   - 2단계 인증(TOTP + 보안키) 확인
   - 비공개 전환 결정(§12 #1)과 Pro 구독 결정(§12 #2)
   - Dependabot alerts 켜기, Actions 기본 권한 읽기 전용
6. **[Claude]** PR 하나로:
   - `.gitignore` 확장
   - 댓글 원문 raw 데이터를 저장소 밖으로 옮기기
   - gitleaks pre-commit 설정
   - PLAN 0단계 산출물(THREAT_MODEL 초안 등)
   - **[나]** 수용 시험: 가짜 키 문자열을 커밋하면 막히는지 확인하고 병합한다.
7. **[나]** 회사의 임직원 가상자산·파생상품 거래 규정과 한국 웹 차단 기준을 확인한다(PLAN 0단계 게이트). **회사 규정이 금지하면 여기서 멈춘다.**
8. **[나]** Anthropic Console:
   - 결제 등록, Workspace `btcbot-prod`·`btcbot-dev` 만들기, 월 한도 설정
   - **키는 아직 발급하지 않는다.**
9. **[나]** 텔레그램:
   - 2단계 인증 비밀번호 설정
   - BotFather로 운영 봇·개발 봇(·제안: 운영 알림 봇) 만들기, 그룹 초대 금지
   - 토큰은 비밀번호 관리자에만 둔다.
10. **[나]** AWS: 계정 만들기, 루트 MFA, 일상용 사용자, 예산 알림 $20. **서버는 아직 만들지 않는다**(1단계 후반에 만든다).
11. **[나]** 바이낸스:
    - 메인 계정: 2단계 인증, 피싱 방지 코드, 출금 주소 화이트리스트
    - 봇 전용 서브계정을 만들 수 있는지 확인한다. 만들어도 되지만 **키는 만들지 않는다.**
12. **[나]** 폰 브라우저로 거래소 웹에 로그인되는지 확인한다(비상 정지 경로).

**완료 기준**: 신뢰 루트 표(§2.3)의 모든 계정에 SMS가 아닌 2단계 인증이 켜져 있다 · (비공개를 택했다면) 로그아웃한 브라우저로 저장소 주소를 열면 보이지 않는다 · 가짜 키 커밋이 거부된다 · 회사 규정 확인 결과가 기록돼 있다.

### 1단계 — 데이터·지표 (2~4주)

1. **[Claude]** uv 프로젝트 뼈대:
   - Python 3.14 고정, `uv.lock`, `exclude-newer = "7 days"`
   - 허용목록 파일(두 층)
   - CI: pytest, ruff, gitleaks, pip-audit, 허용목록 검사. 액션은 SHA로 고정
2. **[Claude]** 허용목록에 ccxt, pandas, pydantic-settings를 추가한다. 공개 시세만 쓰고 키는 쓰지 않는다. 불변조건 테스트를 먼저 쓴다.
3. **[Claude]** matplotlib 차트 시험. mplfinance가 pandas 3에서 되는지 확인한다(C6). 컨테이너 시간대 DB도 확인한다.
4. **[나]** PR마다 한국어 수용 시험 결과를 보고 병합한다. 예: "어제 1H 캔들 24개가 빠짐없이 DB에 있고 거래소 차트의 MA 값과 같다."

#### 1단계 후반 — 서버 구축 (거래 키 없음, **기본**)

**왜 이때인가**: 코드 규칙 전향 모의 기록(A6)과 OI·롱숏비 수집은 24시간 돌아야 한다. OI·롱숏비는 거래소 API가 최근 30일만 주므로, 서버를 3단계에 만들면 그 사이 데이터를 다시 받을 수 없다. 전향 기록은 규칙 고정일 이후의 **진짜 홀드아웃**이라 늦게 시작할수록 G3 때 쓸 자료가 줄어든다 [판정 A6, Q2, Q16] [02 요약 3] (INFRA §2.4·§12, ARCHITECTURE §1.3, DEV_GUIDE 카드 1-14).

5. **[Claude]** PR로 만든다: 수집기(선물 캔들·펀딩비·마크 가격, **OI·롱숏비 매시간**), 전향 기록 앱(`apps/forward_shadow`), Docker Compose(`prod`, FWD_SHADOW 모드), 백업 작업, 간단한 `deploy.sh` v0 (DEV_GUIDE 카드 1-14). 새 패키지는 없다(백업 업로드 도구는 §4.1 확인 필요).
6. **[나]** Anthropic Console `btcbot-dev`에서 개발 키를 발급한다(30분 점검용). 운영 키는 아직 만들지 않는다.
7. **[나]** Lightsail 도쿄 리눅스 2GB를 만들고 고정 IP를 붙인다. **30분 연결 점검**(바이낸스 공개 API 451 여부, 텔레그램 `getMe`, Anthropic 짧은 호출, 시계 오차)을 한다. 텔레그램·Anthropic은 개발용 토큰·키를 잠깐 쓰고 점검 뒤 서버에서 지운다. 문제가 있으면 인스턴스를 지우고 서울 리전으로 바꾼다 (INFRA §2.4).
8. **[서버]** 하드닝 (INFRA §4 우선순위 1):
   - 사람용 사용자 계정, SSH 키 전용 로그인
   - Tailscale 설치 → 공인 SSH 닫기
   - UFW, **unattended-upgrades(자동 설치 켬, 자동 재부팅 끔)**, chrony, Docker Engine + Compose, 로그 제한(10m×5)
9. **[나]** 폰에 Tailscale 앱(과 필요하면 SSH 앱)을 설치하고, 이메일 앱 알림을 켠다.
10. **[나]** healthchecks.io에 가입해 수집·전향 기록 체크와 백업 체크를 만들고 이메일 채널을 연결한다 (INFRA §7.2의 `prod-analysis`·`prod-backup`).
11. **[서버]** 읽기 전용 배포 키를 만들어 GitHub에 등록한다(`ssh.github.com:443`).
12. **[나/PC]** age 키쌍을 만든다. **공개키만** 서버에 둔다. AWS에서 백업 버킷(버전 관리)과 쓰기 전용 자격증명을 만들어 서버 비밀 파일(권한 400)에 넣는다.
13. **[서버]** `deploy.sh <태그>`로 FWD_SHADOW를 켠다. 매일 백업이 시작된다.

**1단계 완료 기준** (서버 부분, INFRA §12와 DEV_GUIDE 1단계에서 가져옴): 451 오류 없음 · 시계 오차 100ms 미만(제안) · 외부 포트 스캔 결과 열린 포트 0개 · 공인 IP로 SSH 응답 없음 · 서버에 어떤 거래 키도 없다 · 전향 모의 기록이 24시간 돌고 데드맨 핑이 끊기지 않는다 · OI·롱숏비가 7일 연속 결측 없이 쌓인다(제안) · 백업 파일이 서버 밖에 쌓인다.

### 2단계 — G1 백테스트 (3~6주)

1. **[나]** 집 PC에 Docker Desktop(윈도는 WSL 2 포함)과 Git을 설치한다. 필요하면 Python 3.14와 uv도 설치한다.
2. **[Claude]** 백테스트 전용 환경(별도 락파일)에 재생기, freqtrade 전략 파일, 통계 스크립트, 시도 레지스트리를 만든다.
3. **[나/PC]** freqtrade 공식 이미지를 digest로 받는다. 선물 데이터를 내려받아(`--trading-mode futures`) 백테스트를 실행하고, 결과를 Claude 세션에 전달한다(방법은 DEV_GUIDE.md).
4. **통과 규칙이 0개면 3단계 이후 개발을 멈춘다** (D16).
5. 2단계 동안 서버는 수집·전향 기록·백업을 계속한다 (INFRA §12). 서버에는 여전히 거래 키가 없다.

### 3단계 — Claude 섀도 분석 + 텔레그램 신호 (주문 없음)

서버·하드닝·Tailscale·healthchecks·백업은 **1단계 후반에 이미 끝나 있다.** 이 단계에서는 비밀 파일과 서비스만 더한다. 1단계 후반을 건너뛰었다면 1단계 후반 5~13번을 먼저 한다.

1. **[나]** Anthropic Console `btcbot-prod`에서 운영 키를 발급한다. 이 키와 텔레그램 운영 봇 토큰(·제안: 운영 알림 봇 토큰)을 서버 비밀 파일(`/etc/btcbot/prod/secrets/`, 권한 400)에 넣는다. SSH 세션 안에서만 붙여 넣는다.
2. **[Claude]** anthropic, python-telegram-bot[job-queue]를 허용목록에 추가하고 분석·알림(A)을 켜는 PR → CI 통과 → 버전 태그 → **[서버]** `deploy.sh <태그>`. prod가 FWD_SHADOW에서 PAPER로 바뀐다. 전향 기록과 수집은 끊기지 않고 이어진다.
3. **[나]** 백업 복구 연습을 1회 한다 (INFRA §12).
4. **완료 기준**: 외부 포트 스캔 결과 열린 포트 0개(유지) · 모든 알림 첫 줄이 [PAPER] · 다른 텔레그램 계정으로 버튼을 눌러도 아무 일이 없다 (PLAN §7.1) · 복구 연습 성공.

### 4단계 — 주문 게이트웨이 + 리스크 가드 (G3와 병행)

1. **0단계 법·규정 게이트를 통과했는지 먼저 확인한다.**
2. **[나/서버]** 바이낸스 테스트넷·데모:
   - 가입한다(방법 확인 필요).
   - **[서버]** Ed25519 키를 만들고, **[나]** 공개키를 등록한다(IP = 서버).
   - staging 비밀 파일에 넣는다.
3. **[나]** 개발 봇 토큰과 Anthropic 개발 키를 staging 비밀 파일에 넣는다.
4. **[Claude]** 주문 게이트웨이(ccxt 직접), 주문 방화벽, 프로세스 분리. **새 패키지는 없다.** 주문·가드 코드는 별도 리뷰 세션이 검토한다.
5. PoC 최우선: 체결 전에 closePosition 손절을 미리 걸 수 있는지 확인한다 (PLAN C1).

### 5단계 — 운영 강화

1. **[나/PC]** 독립 감시자:
   - 바이낸스 읽기 전용 키(IP 정책 확인, C5)
   - 전용 healthchecks 체크(`/fail`로 이메일 경보, 제안)
   - PC 절전 끄기
2. **[나]** 백업 복구 연습 1회, 폰 브라우저로 비상 정지 연습, 탁상훈련 4종.
3. **[나]** Tailscale ACL로 LIVE 단계의 권한 완화 조작을 PC에만 허용한다(기능 확인, C10).

### 6단계 직전 — 소액 실거래 준비

1. 전환 조건 D17 (1)~(5)를 모두 확인한다.
2. **[서버]** 실거래 Ed25519 키를 생성한다.
3. **[나/PC — 두 번째 기기]** 거래소 웹에서 서브계정 API 키를 등록한다. 권한은 선물 거래 + 읽기, IP는 서버 1개.
4. **[나]** prod 비밀 파일에 넣고 발급일·교체 예정일을 기록한다.
5. **[나]** 서브계정에 정한 금액만 이체한다(D20). 자동 충전은 하지 않는다.

### 하지 말 것 (모든 단계)

- 키·토큰을 Claude 대화, GitHub 이슈·PR, 메모 앱, 스크린샷에 붙이지 않는다.
- 운영 봇 토큰으로 PC나 클라우드 세션에서 시험하지 않는다(409 충돌, 유출).
- 서버에서 `pip install`로 직접 설치하지 않는다.
- 윈도 Docker로 운영하지 않는다. 공인 SSH 포트를 열어 둔 채로 두지 않는다.
- 실거래 키를 6단계 전에 만들지 않는다.
- 서버 자동 재부팅을 켜지 않는다. 재부팅·배포는 **안전 상태**(포지션 0, 미체결 주문 0, 승인 대기 0)에서만 한다. 긴급 수정 예외는 INFRA §5.3·§10.7을 따른다 [판정 SEC-05].
