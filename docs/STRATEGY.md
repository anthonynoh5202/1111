# 차트 분석 기법 v0.2 — "기준봉·허리 + 캔들·거래량 + 이평선"

> 작성일: 2026-09-29 · 상태: 초안 v0.2 (v0.1을 리서치 보고서 2건으로 갱신)
> 근거: [research/chartpro/REPORT.md](../research/chartpro/REPORT.md) (이하 **CP**), [research/wonyotti/REPORT.md](../research/wonyotti/REPORT.md) (이하 **WY**)
> 전제: BTC/USDT 선물 · **1시간봉 신호 + 4시간봉 방향 + 15분봉 타이밍** · 사람이 텔레그램 버튼으로 승인하는 **반자동** 구조 ([PLAN.md](./PLAN.md))

> ⚠️ **근거 신뢰도가 전반적으로 낮다. 먼저 읽을 것.**
> - **차트프로**: 자막 0/138건. 강의 본문을 한 줄도 확인하지 못했다. 영상 제목·해시태그·시청자 댓글(쓸 만한 요약 약 25개)에서 뽑은 **개념 수준**이다. 신뢰도 "상" 항목이 없다. 수치는 전부 **제안값(확인 필요)**이며 차트프로가 제시한 값이 아니다. (CP §1)
> - **워뇨띠**: A등급 원문(BitMEX 인터뷰·AMA, 디시 원글)을 **한 건도 직접 읽지 못했다**. 모두 검색 요약을 거친 문장이고, 여러 정리글이 같은 원문을 옮긴 것이라 "교차 확인" 숫자도 독립 확인이 아니다. 표기 등급보다 **한 단계 낮춰** 읽는다. (WY §1)
> - 따라서 이 문서의 모든 진입 규칙은 **백테스트 전 가설**이다. 리스크 규칙만은 근거와 무관하게 보수적으로 고정한다(§8).

## 2. 분석 구조: 코드는 측정, Claude는 해석, 규칙은 안전장치

```
[코드] 객관적 수치 계산 ── 매번 같은 결과, 검증 가능
   │   캔들·꼬리·거래량 배수, 기준봉·기준가·허리, 이평선, 전고저, 윗꼬리 가격대, 닮은꼴 유사도
   ▼
[코드] 시나리오 1차 판정 (◎ 조건만) ── 조건이 하나도 맞지 않으면 Claude 호출 생략(관망)
   ▼
[Claude] 수치 + 차트 이미지 → 맥락 해석 (✕·○ 항목)
   │   "아는 구간"인지, 패턴 해석, 닮은꼴 해석, 무효화 조건, 진입·손절·익절 제안
   ▼
[규칙] 하드 가드 ── Claude가 뭐라고 하든 코드가 강제 (§8)
   ▼
[사람] 텔레그램 버튼 승인
```

v0.2에서 달라진 점: **코드가 먼저 시나리오 후보를 거른다.** Claude는 코드가 올린 후보를 해석하고, 후보에 없는 시나리오는 "관망"으로만 낼 수 있다(패턴 P10은 Claude 참고 의견으로만 `evidence`에 적고 확신도 가점 금지).

## 3. 다중 타임프레임

| 타임프레임 | 역할 | 보는 것 | 근거 |
|---|---|---|---|
| 4시간봉 | **큰 방향 + 기준봉 탐색** | 이평선 배열, 허리 위/아래, 4H 기준봉 | C3, P2 |
| 1시간봉 | **신호 발생** (분석 주기) | 기준봉(거래량 급증 봉), 기준가 지지/이탈, 윗꼬리 회복, 돌파 | C1, P1~P5, W1 |
| 15분봉 | **진입 타이밍** + 기준가 산출 | 지지 확인 캔들, 되돌림, 기준봉 내부 가격대(기준가) | P3, CP R13 |

- 4H 방향(허리 위/아래 + 이평 배열)과 반대인 신호는 **보내지 않는다** (P9, v0.1의 "확신도 낮춤"보다 강화).
- 1분·5분봉 **신호**는 쓰지 않는다 (반자동 구조 + W5). 기준가 산출에 5분봉 데이터를 **계산용으로만** 쓸지는 백테스트 후 결정 (CP R2 원문은 "5분봉으로 쪼갬").
- BTC는 24시간 시장이므로 "일봉을 쪼갠다"를 적용할 때 하루 경계는 **UTC 00:00**으로 고정한다 (CP §4 주의).

## 4. 코드가 계산하는 수치 (정의)

숫자는 모두 **제안값**이다. 두 보고서 어디에도 확정 수치가 없다. 백테스트로 조정한다.

| 항목 | 정의 (v0.2) | 근거 · 신뢰도 |
|---|---|---|
| 몸통 크기 | \|종가 − 시가\| | 기본 |
| 장대봉 | 몸통 ≥ 최근 20개 평균 몸통 × 2 | v0.1 가정 (신뢰도 없음) |
| 꼬리 비율 | 꼬리 길이 ÷ (고가 − 저가). 긴 꼬리 ≥ 50% | v0.1 가정 |
| 거래량 배수 | 현재 거래량 ÷ 최근 20개 평균 | C1 |
| 큰 거래량 / 폭발 | 배수 ≥ 2 / ≥ 3 | v0.1 가정, CP R1 제안 k=3 |
| **기준봉** (신규) | 1H·4H에서 거래량 배수 ≥ 3인 봉. 최근 것부터 최대 3개 유지 | P1 · 하~중 · ○ |
| **기준마디** (신규) | 기준봉의 고가~저가 구간 (여러 봉 구간인지 미확인) | P2 · 중 · ○ |
| **허리** (신규) | 기준마디 (고가 + 저가) ÷ 2. 대안: 몸통 중간 — 둘 다 계산해 백테스트 | P2 · 중 · ◎ |
| **기준가** (신규) | 기준봉 시간 구간을 15m로 쪼갠 뒤 **구간 VWAP**. 대안: 최다 거래량 15m 봉의 종가 | P3 · 하 · ○ |
| **건강한 조정** (신규) | 고점 이후 되돌림 구간 평균 거래량 < 직전 상승 구간 평균 거래량 | P4 · 중 · ◎ |
| **조정 중 거래량 급증** (신규) | 되돌림 구간에서 거래량 배수 ≥ 3인 음봉 발생 | P4 · 중 · ◎ |

## 6. Claude 출력 형식 (JSON)

```json
{
  "direction": "LONG | SHORT | NEUTRAL",
  "scenario": "L1 | L2 | L3 | L4 | L5 | S1 | S2 | S3 | S4 | NONE",
  "confidence": 0.0,
  "summary": "한 줄 요약",
  "evidence": ["근거 1", "근거 2"],
  "key_levels": { "base_candle_time": "", "waist": 0, "base_price": 0, "wick_zone": 0 },
  "entry": 0,
  "entry_plan": [{ "price": 0, "size_ratio": 0.5 }, { "price": 0, "size_ratio": 0.5 }],
  "stop_loss": 0,
  "take_profit": [0, 0],
  "invalidation": "이 조건이 깨지면 시나리오 무효",
  "higher_tf_alignment": "4시간봉 방향(허리·이평 배열)과 일치 여부",
  "analog_note": "과거 닮은꼴 해석(있으면)",
  "is_known_pattern": true
}
```

- `invalidation`은 **필수**다 (C5).
- `key_levels`의 숫자는 **코드가 계산한 값을 그대로 복사**한다. Claude가 새 수준을 만들면 코드가 거부한다.
- `scenario`는 코드가 올린 후보 중 하나여야 한다. 아니면 NEUTRAL 처리.
- `is_known_pattern`(워뇨띠의 "아는 구간" W3·WY S8의 근사, ✕ → Claude 판단): false이면 확신도 상한 0.6.
- `entry_plan`은 §7 분할 진입을 쓰는 경우에만. 합계는 1.0.

## 9. 검증 계획

1. **1단계 백테스트 (◎ 규칙만)**: L1·L3(①②)·S2·S3, 허리 필터, 건강한 조정 필터를 과거 1~2년 BTC/USDT 1H/4H/15m로 검증. 허리(고저 중간 vs 몸통 중간), 기준가(VWAP vs 최다 거래량 봉), 기준봉 배수(2/3), 손익비 1.5 vs 2.0을 비교.
2. **2단계**: L5·S1(윗꼬리), 과거 닮은꼴 가점(○) 추가 후 가점 유무 비교. 닮은꼴은 **룩어헤드 금지**(비교 대상은 신호 시점 이전 데이터만).
3. **Claude 페이퍼 트레이딩**: 코드 후보 + Claude 해석 신호를 기록만 하고 사후 집계. 코드 단독 대비 Claude가 성과를 개선하는지 확인.
4. 성과가 나쁜 시나리오는 끄거나 조건을 조정. L4·S4는 성과 확인 전까지 확신도 상한 0.6.
5. 워뇨띠 원장 원본을 받으면(WY 후속 과제 1) 손실 분포·보유 시간으로 §7·§8 파라미터를 재검토하되, **완화 방향으로는 바꾸지 않는다**.
6. 상업화 시 원장 공개자의 "유료 판매 삼가" 요청을 따른다 (WY §4 주의).
