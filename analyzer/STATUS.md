## 알아낸 것

- **클라우드에서 읽히는 시세**: 바이낸스 선물 실시간과 Bybit는 위치 차단으로 안 된다. 바이낸스 현물 실시간, 바이낸스 선물 보관소(하루 이틀 늦음), OKX는 된다.
- **현물로 신호 대체**: 안 된다. 일치 87%지만 확인 기간 초과 수익이 절반 아래다(`research/spot_vs_futures/`).
- **OKX로 신호 대체**: 미리보기로만 된다. 일치 약 90%, 확인 기간 초과 수익은 바이낸스의 60%(t 1.79)다(`research/okx_vs_futures/`).
- **처음 보는 자료 성적**(2026-09-29~11-16, 290봉, 롱 신호 52번): 초과 수익 −0.122%p (t −0.65). 표본이 작아 판정할 수 없다. 버리는 기준(t −1.5 아래)에는 닿지 않았다.

## 보안 검토 (2026-11-19)

저장소 전체를 검토하고 고쳤다(트레이딩뷰 연결에 대한 항목은 연결을 지우면서 뺐다). 시험은 `analyzer/test/security.test.cjs`.

| 찾은 것 | 고친 것 |
|---|---|
| 대시보드 서버가 잘못된 주소 한 번에 꺼질 수 있었다 | 주소 해석 실패를 400으로 답한다. GET·POST 밖의 방식은 405 |
| 다른 사이트가 대시보드를 틀(iframe)에 넣어 "지금 분석"을 누르게 할 수 있었다 | `frame-ancestors 'self'`, `X-Frame-Options` 추가 |
| 단독 분석기 화면이 어디든 접속할 수 있었다 | 접속 제한(CSP): 글꼴과 `fapi.binance.com`만 |
| 텔레그램 토큰이 오류 글에 섞여 나올 수 있었다(토큰이 주소에 들어감) | 오류 글에서 토큰을 지운다. 토큰·chat_id 모양을 먼저 확인한다 |
| `secrets.json`이 실수로 git에 올라가도 그대로 보냈다 | git에 올라가 있으면 보내지 않고 멈춘다. 다른 사용자가 읽을 수 있으면 경고 |
| 보고서의 개발용 부품(`pdf-to-img` → `tar`)에 심각 등급 취약점, 설치 스크립트 실행 | 기본 설치에서 뺐다. `pdfkit`은 판을 고정(0.15.2). 설치는 `npm ci --omit=dev --ignore-scripts` |
| OKX·텔레그램 요청이 다른 주소로 넘기는 응답을 따랐다 | 따르지 않는다(`redirect: "error"`) |
| 비밀 파일이 다른 폴더에 있으면 `.gitignore`가 못 막았다 | `secrets.json`, `.env`, `*.pem`, `*.key`를 어디서든 무시 |

확인만 하고 그대로 둔 것:

- 올라간 파일과 전체 기록에 실제 토큰·키는 없다(다른 브랜치의 시험용 가짜 값만 있다).
- 플랫폼·보고서의 운영 부품에는 알려진 취약점이 없다(`npm audit` 0건).

남아 있는 위험(코드로 못 고치는 것):

- 텔레그램 토큰은 주소에 들어가는 방식이라, 클라우드에서 보내면 중간의 프록시가 토큰을 볼 수 있다. 토큰이 새면 BotFather에서 바로 폐기하고 새로 발급한다.
- 대시보드의 실행 토큰은 이 PC에서 대시보드 주소를 읽을 수 있는 프로그램이면 얻을 수 있다. 이 PC 안의 악성 프로그램은 막지 못한다.
- 옛 커밋(개인 주소가 들어 있던 것)은 브랜치에서는 사라졌지만 GitHub 서버에는 한동안 남아, 커밋 번호를 아는 사람은 볼 수 있다. 완전히 지우려면 GitHub 고객센터에 요청해야 한다.

## 클라우드 환경 메모

- **보고서 파이프라인을 클라우드에서 돌려 봄(2026-11-19)**: `fetch`(OKX 6개 타임프레임)와 `build`(6쪽 PDF, 한글 폰트 포함)는 된다. 단, 명령 앞에 `NODE_USE_ENV_PROXY=1`을 붙여야 한다. 클라우드는 프록시를 거치는데 Node의 `fetch`가 기본으로는 프록시를 쓰지 않아서, 안 붙이면 "OKX 시세를 읽지 못했습니다"로 실패한다. 예: `NODE_USE_ENV_PROXY=1 node run.cjs fetch`
- `send`(텔레그램)는 클라우드에서 아직 안 해 봤다. 허용 주소에 `api.telegram.org`가 없고, 토큰을 둘 곳을 정해야 한다. 텔레그램은 토큰이 주소에 들어가는 방식이라, 환경의 "네트워크 비밀"(헤더에 넣어 주는 방식)로는 넣을 수 없다.
- 보고서 1쪽에서 차트 아래 날짜 눈금과 "데이터 …" 설명 줄이 겹쳐 보인다(고칠 것).

환경 "기본"의 허용 주소: `data-api.binance.vision`, `data.binance.vision`, `www.okx.com`(이번에 추가), `docs.nvidia.com`(원래 있던 것). `fapi.binance.com`과 `api.bybit.com`은 위치 차단이라 추가했다가 다시 뺐다.
